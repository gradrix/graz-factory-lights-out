# Eventual autonomous delivery

Status: accepted destination; staged implementation proposed. Date: 2026-10-02.

**User decision:** publish the current small factory, delete previous implementation/docs and the reset archive, and plan eventual end-to-end operation with local LLMs, understandable reasoning tasks, tools, automatic container setup, external visibility, logs/progress, web search and headless browsing.

**Consequence:** the initial release boundary remains accurate for implemented behavior, but no longer defines the eventual product ceiling. [Roadmap](../../roadmap.md) stages visibility, review, preparation, tools, planning/integration and autonomous delivery. This supersedes treating a dashboard or automatic integration as permanently out of scope in the first-release notes. Production actions still require a declared target and authority; this planning request does not execute them.

Autonomous operation starts from a bounded brief and policy. It can stop with evidence for an irreducible decision or exhausted recovery; such a run is not counted as successful delivery. External search and dependency acquisition require network access. Local inference and prepared execution remain independent of cloud LLM services.

**Agent proposals:** initial Python/Node profiles, stage order, one GPU inference request at a time, and the numeric qualification gates. These are testable starting policies, not user-selected thresholds or proven success rates. Each stage's result can revise later detail without restoring the previous factory design.

Supporting evidence: [first pilot](../../pilot-results.md) showed both useful repairs and false confidence from incomplete checks; [primary-source research](../../research/autonomy-feasibility.md) supports the tool route. Remaining uncertainty: actual model reliability, useful task/context sizes, review quality and unattended project coverage.
