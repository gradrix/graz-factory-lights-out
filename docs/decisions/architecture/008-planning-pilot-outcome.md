# Keep planning advisory; strengthen executable verification

Status: accepted direction, 2026-10-04. Decision maker: agent under the user's continuing authorization for incremental, tested local autonomy.

Keep direct bounded assignments as the maintained execution path. The isolated two-task planner has not earned a permanent parent scheduler. Next, test whether a fresh local reviewer with bounded, read-only execution can catch concrete requirement defects that text-only review missed. This is a hypothesis to qualify before maintained promotion.

The actual RTX5090 comparison used two fresh multi-file increments and four frozen, equal-ceiling arms:48 total requests and1800seconds each, including all planning/review overhead. Direct/planned manifest work took321.077/494.785seconds and23/36requests. Both passed Factory checks; independent execution then confirmed different A6 failures: a test fixed to `/workspace`, and an invalid README request advertised as successful. The API planned/direct arms both exhausted48requests, after873.540/963.986seconds, without final acceptance. All four cleaned up and confirmed the unchanged model idle. No operator hints or retries were added during these arms.

This pilot produced no independently complete increment. It is two cases with one run per arm, not a reliability estimate or statistical comparison. The plans and checked snapshot handoffs worked mechanically; their contribution to completion was not demonstrated. Failures remain failures, including when supplemental diagnostic controls pass.

Independent executable checks discriminated each manifest defect from a narrowly corrected disposable control. API probes also identified concrete shape/depth/HTTP errors. This supports investing the next experiment in executable verification. It does not yet prove that the local model will choose useful probes, interpret results correctly, or avoid false rejection. Qualification must include defective and conforming candidates, genuine execution evidence, bounded resources, unchanged source, and lifecycle controls.

The earlier [prototype route](../../../.scratch/autonomy/planning-prototype-route.md) proposed a durable shared budget as the first maintained follow-up. That remains useful, but this decision moves verification discovery ahead of that production change because observed false acceptance directly blocks robust unattended delivery. Prototype budgeting does not establish maintained durable budgets across resume. No factory implementation, serving profile, automatic integration, or original repository has been changed by this decision.
