# Domain docs

## Before exploring

This repo uses a single-context layout.

Read root `CONTEXT.md`, then relevant decisions in `docs/adr/`.
If either is absent, proceed silently. Domain modeling creates
documentation lazily when terms or decisions are resolved.

## Vocabulary

Use domain terms as defined in `CONTEXT.md` in issue titles,
proposals, hypotheses, and tests.

If a needed concept is missing, reconsider the terminology or
note the gap for domain modeling.

## Decision conflicts

Explicitly flag proposals that contradict an existing ADR,
identifying the ADR and explaining why it merits reconsideration.
