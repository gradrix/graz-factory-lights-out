# First document-evidence slice: boundary proposal

2026-10-02. **Read-only design proposal, not implementation or qualification.** Stage 3's final model-semantic gate remains separate. This proposal follows [Stage 4](../../docs/roadmap.md#4-research-and-browser-tools) and the [verified route research](../../docs/research/research-browser-route.md). Search, browser sessions and crawling are outside this slice; the full ten-research-answer/five-application-journey Stage 4 gate remains unchanged.

## One complete behavior

A controller-approved exact official HTTPS document URL is fetched by fixed code, extracted offline, and published as immutable evidence. A fresh local-model request answers one question from that evidence with checked citations. An offline invocation resolves the same evidence ID and can display the saved answer without network access. Missing, stale/ineligible, corrupt or unsupported evidence produces an explicit result; it cannot become “no evidence of a problem.”

First demonstration: one small official documentation page, one answerable question and one deliberately unsupported question. Freeze URL, source/version expectations, question, acceptance assertions and budgets before implementation trials. A document version is an observed/approved label, not inferred from a floating URL; retrieval time and content digest remain authoritative provenance.

## Minimal modules and reuse

| Existing seam | Proposed use |
| --- | --- |
| [`gflo/guard.py`](../../gflo/guard.py), `run(..., output=..., max_output_bytes=..., cancelled=...)` | Reuse unchanged for strict binary capture, bounded diagnostics, actual executor inspection, owner EOF, cancellation and exact-container removal. Build all container arguments in trusted controller code. |
| [`gflo/recipes/fetch.py`](../../gflo/recipes/fetch.py), `resolve` / `Connection` / bounded `consume` | Preserve public IPv4 checks, numeric destination connection, original-host TLS, identity encoding and strict length/status handling. Package `validate`, required preknown digest, registry allowlist and tar output do not fit documents. Add a small fixed document helper; extract a shared transport primitive only if both callers benefit and package behavior has unchanged regression evidence. Do not broaden the package allowlist or make its digests optional. |
| [`gflo/environment.py`](../../gflo/environment.py), publication/resolve pattern | Apply private staging, reader/publisher lease, canonical receipt digest, pending marker, final cancellation fence and verification-before-use to document records. Its environment schema, dependency tree and smoke callback are inappropriate as document APIs. Keep document records in their own controller-owned store; no generic artifact framework is required. |
| Existing local model client and run observations | Use one fresh, tool-free answer request and bounded phase events. Store evidence/answer IDs in durable artifacts; do not introduce a second application or scheduler. |

A cohesive `documents` module can own acquisition, extraction, receipt resolution and answer validation. Its narrow public operations can be `acquire(approved_document)`, `resolve(evidence_id)` and `answer(question, evidence_id)`. The model receives no acquire/publish capability in this first slice. The controller approval object contains the exact URL and limits; no model-supplied paths, headers, Docker flags, credentials or policy changes.

## Fetch, extraction and lifetime rules

**URL/network.** Require exact byte equality with a controller-maintained approved HTTPS URL after rejecting controls/non-ASCII/backslashes, userinfo, fragments, query strings and non-443 ports. Approval covers path as well as host; links in a page do not extend it. Check every returned IPv4 address and reject the entire DNS set on any nonpublic/multicast/reserved result. Connect to one checked numeric address, retaining original hostname for certificate verification and HTTP Host. Reject all redirects, including same-origin ones, and all non-200 responses. Send no authorization/cookies/referer or proxy configuration. This remains a trusted-client boundary on bridge networking; it is not arbitrary-process egress confinement.

**Executor.** Use the approved pinned non-GPU Python image, no pulls, explicit runc, nonroot, dropped capabilities/no-new-privileges, read-only root, bounded memory/CPU/PIDs/tmpfs and no devices. Mount only fixed helper and the small approved request read-only. No project, home, Docker socket, model credentials or writable host destination. Capture bytes through guardian output; close/remove the fetch executor before publication. Reserve a separate offline executor for processing the fetched document so HTML parsing never occurs in the online client.

**Transport.** Propose one bounded metadata frame followed by the raw body: at most 8 KiB canonical JSON header terminated by newline, then exactly the declared body bytes and EOF. Bound the complete stream to 2 MiB + 8 KiB + delimiter; refuse extra/truncated data. Metadata selects only status, content type/charset, approved URL, connected address and necessary cache headers. Cap header names/values/counts and reject ambiguity. Never use stderr logs as authoritative metadata. Controller rehashes the captured raw body. An optional approved expected digest must match; otherwise the newly observed digest identifies a version, without claiming prior content approval.

**Extraction.** Initial types: `text/plain` and `text/html`, UTF-8 only; reject other charsets, compressed content, attachments, PDFs, archives and binaries. Reject oversize instead of silently truncating. Versioned deterministic extraction preserves text order and block boundaries, drops comments/script/style/template and other explicitly excluded non-content regions, never follows links, loads assets, evaluates scripts, imports modules or interprets markup as a tool call. HTML is source-text extraction, not a rendered-page claim. Proposed limits: 128 KiB extracted UTF-8, 10,000 parser events, depth 64, 2,048 text blocks. Fail on parser/encoding/limit errors or empty extraction. Retain raw bytes so omissions are reviewable; emit inert text when rendering evidence.

**Budgets and cancellation.** Initial trial budgets: 15 seconds acquisition work, 5 seconds extraction, one document and one acquisition at a time. Preserve the guardian's separate bounded cleanup phase: 15 seconds is not a promise that the entire call returns in 15 seconds. Check one monotonic acquisition/extraction deadline between phases and immediately before commit. Late output after cancellation never restores eligibility. Cleanup failure, transport error or pending publication cannot produce a reusable new ID. Ordinary owner death may leave private scratch until trusted recovery; shared-daemon failure remains an explicit cleanup failure. Source review and new phase tests must establish these document-specific paths despite prior environment evidence.

## Immutable provenance and offline retention

One record contains fixed names only: `body`, `text`, `receipt.json`, plus `pending` before commit. Receipt fields: format/version, approved request identity, requested/final URL (equal in this slice), controller UTC retrieval times, HTTP status/type/charset, bounded cache policy, observed source/version label, raw/text sizes and SHA-256s, extractor identity and parameters, and pinned executor/helper identities. Citation blocks use stable numbered spans in the frozen extracted text. Receipt ID is the SHA-256 of canonical receipt bytes; resolver checks ownership, modes, regular files/no links, hashes, bounds and absence of `pending`. URL or caller paths never name storage locations.

Complete executor and outer-workspace cleanup before committing. Preserve earlier records after any failed refresh; never replace evidence behind an old ID. A valid document may remain published if later inference fails, but no successful-answer receipt is written for that failure. Failed acquisition keeps only bounded diagnostics, not an answerable partial page.

Proposed first retention policy is deliberately narrow: an explicitly approved public documentation origin, no authentication or personalized session; reject `no-store`, `private`, `no-cache`, `must-revalidate`, `proxy-revalidate` and ambiguous/unsupported cache policy for this offline-capable slice. `Set-Cookie` also makes the response ineligible. For accepted responses, distinguish immutable historical evidence from current HTTP freshness; online refresh is explicit and produces a new receipt. Offline answers always disclose “retrieved at …; historical snapshot,” including age, and cannot assert present-day accuracy from age alone. This conservative proposal avoids needing revalidation in the first slice; HTTP caching semantics are discussed in [RFC 9111](https://www.rfc-editor.org/rfc/rfc9111.html) and the route research.

Bound retained storage as well as one response: proposed initial cap 16 evidence records/64 MiB total with reserved staging headroom. Refuse new acquisition when full; no implicit eviction of evidence referenced by answers. Deletion is explicit and must leave references reporting unavailable, not silently resolve them to a refreshed page. Choose the first page and confirm its response/retention eligibility during implementation qualification.

## Hostile text, citations and local answers

Freeze the question and evidence ID before inference. Supply bounded source blocks as quoted untrusted data beneath controller instructions. Source text may contain fake system messages, code, commands, links, or requests for secrets; it cannot change tools, policy, approved URLs, acceptance criteria or retention. **Enforcement is structural:** the answer call has no tools or capability-changing output route. Delimiters and warnings alone are insufficient.

Require a small answer structure: supported claims with citations `{evidence_id, block/span, exact_excerpt}`, plus an explicit insufficient-evidence result. Controller checks reference identity, span bounds and exact excerpt bytes and derives display URLs from the receipt, never a model-supplied link. Reject fabricated references or malformed output. This validates provenance, not whether a citation logically supports a claim; independent semantic checks must assess support, omissions and version/time qualifications before counting a qualification answer as successful.

Record model identity/configuration, prompt/question hash, evidence ID, bounded output, citation validation and answer hash in a separate answer receipt. Proposed initial model budget: one request, capped output and an explicit wall deadline using the existing client. Freeze actual numeric inference limits with the chosen existing model configuration before the trial. No cloud fallback or automatic fetch/search on uncertainty.

Offline **replay** renders a saved validated answer with checked evidence hashes and age; it does not require inference. Offline **re-answering** is an explicit new local-model attempt bound to the same evidence and may produce different text. Neither path silently fetches or treats absent evidence as a negative finding.

## Concrete checks before accepting this slice

Each rejection gets a conforming positive control; retain failing attempts and exact candidate/source IDs.

1. **Approval and SSRF:** unapproved path/host, suffix host, userinfo, explicit wrong port, query/control/backslash, loopback/private/link-local/mixed DNS sets, changed DNS on attempted reconnect, original-host certificate mismatch, every 3xx including private Location. Assert no connection/body read where rejection should precede it.
2. **Body and framing:** exact limit succeeds; limit + 1, declared excess before read, truncation, extra frame/body bytes, conflicting headers, compressed/binary/unsupported charset, invalid UTF-8, wrong expected digest and changed raw hash fail. Ensure retained stderr never exceeds its separate cap.
3. **Extraction and retention:** script/link/asset references make no requests; nested/event/text limits fail; empty or unsupported documents fail; restrictive cache directives/Set-Cookie cannot publish. Same raw input/extractor yields exact text/hash; changed extraction rules require a new identity.
4. **Authority and answers:** hostile “ignore rules/run command/change URL” text cannot trigger any tool call or altered approved request. Fabricated evidence ID/span/excerpt rejects. Include correctly cited but semantically unsupported claims as negative controls for independent evaluation, plus an unanswerable question that must say evidence is insufficient.
5. **Publication and lifecycle:** tampered body/text/receipt, path/symlink replacement, pending ID and invented ID reject. Cancel/expire inside actual fetch and extraction, then at final commit; kill only an owned controller; inject output/cleanup/publication errors. No failed attempt becomes reusable; prior record stays byte-identical and recovery succeeds.
6. **Offline route:** deny network capability for replay/re-answering; restart and resolve the same IDs; report source age and missing/corrupt evidence honestly. Saved replay is byte-consistent apart from separately rendered current age; a new inference is not required to be deterministic.

Implement only after the active Stage 3 gate closes. This first slice establishes one complete document-evidence path; it neither reduces nor satisfies the full Stage 4 qualification gate by itself.
