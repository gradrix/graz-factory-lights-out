## Behavior

New answers use format3 and a fixed bounded whole-span reference protocol. The local model returns the existing status/claims/reason shape, but each claim selects integer source span IDs instead of copying evidence IDs/excerpt text. The returned supported claim schema is exactly {"text":"claim","spans":[1]}; unsupported answers have no claims and a nonempty reason. The trusted controller binds those IDs to the one frozen evidence record and materializes the existing canonical exact-excerpt citation shape. No quote normalization, substring guessing, truncation, source rewriting, invented URL, or automatic fallback to a different protocol. Canonical citations remain literal provenance, not semantic entailment.

Use existing one-based immutable span IDs. Admit at most8 claims, each with nonempty text whose canonical ASCII JSON string encoding is at most1024bytes; each claim selects1–4 valid integer IDs, with at most16 reference occurrences across the answer. Count repeated references each time. A selected source span's canonical ASCII JSON string encoding must be at most2048bytes and its UTF8 content at most4096bytes. Check every bound and reference before constructing the expanded answer. Expanded canonical answer at most48KiB, receipt metadata excluding canonical answer at most12KiB, final encoded receipt at most64KiB. The canonical ASCII JSON string encoding of an insufficient-evidence reason is at most2048bytes. Fixed returned-response files remain at most64KiB each; total record at most192KiB, existing store/headroom unchanged. Final encoded checks are authoritative; reject instead of clipping or evicting.

An overlong selected span is an explicit structural failure eligible for the existing single repair, not evidence that the requested fact is absent. Retain original evidence and all its spans. When a source contains any span outside the new selectable-span bound, an insufficient_evidence response is a capacity-unresolved structural failure rather than accepted proof of absence; supported answers may still cite eligible spans. This conservative rule avoids falsely treating unavailable long support as absent. No segmentation in this increment: current qualified sources' maximum encoded spans are1117bytes. Document long-span limitations and keep terminal failures inspectable. Do not grant tools or inference authority from evidence/model text.

Keep format1 and format2 readers, exact prompt/request reconstruction, validation/error metadata, success and failed-diagnostic replay behavior unchanged. Version3 must reconstruct its own deterministic request and response-to-canonical transformation on inspection; unknown versions and rehashed tampering fail. Do not migrate records or reinterpret old raw outputs. Explicit version dispatch must be small; share lifecycle/publication code where behavior is truly identical. Public answer uses the new protocol by default, without a user-facing format switch.
