# Stateful ai-gamer batch atomicity qualification

The local model planned and implemented a real SQLite defect repair and generated
regression tests. The first accepted, independently audited candidate is delivered
in [ai-gamer PR 2](https://github.com/gradrix/ai-gamer/pull/2). Its implementation and
tests were copied unchanged from factory acceptance; no manual logic or test correction.
This was supervised task selection and independent validator design, not autonomous
bug discovery or general database reliability qualification.

## Defect and fixed behavior

Baseline ai-gamer main: `9a0a4384b9b727c02f0f2c168c7abc43a4e076bf`.
`RecorderDb.addMoves` returned -1 after a constraint failure but left earlier rows in
an open transaction. A later `createPlayer` committed those rows. The minimized
`reproduce.py CHECKOUT` prints `pending_after_failure: True` and a leaked valid move
on baseline, and fails its assertion. A separate reader saw no row before that later
commit; explicit rollback prevented the leak. This distinguishes missing rollback from
premature commit or stale reads. The delivered candidate prints False and an empty list.

The fix rolls back before releasing the writer lock. Independent checks cover success,
empty batches, enumerate-based indices, supplied dates/values, first/later failure in
four NOT NULL fields, preservation of committed rows, subsequent unrelated writes and
recovery. A held-out real deferred foreign-key violation additionally exercises failure
at COMMIT. No replacement database or connection is used. All 22 new and existing winner
tests pass; 87 other original files remain unchanged. Broader training/legacy test suites
were not qualified; some old test files still import an obsolete `models` package.

## Frozen experiments and limitations

| Campaign | Complete acceptance | Scope |
| --- | ---: | --- |
| atomic-moves-v2 | 0/3 | Factory runtime at 113e01e, before failure-local windows |
| atomic-moves-v4 | 1/3 | Same requests/policies, with failure-local windows |

Every request and policy in v4 was asserted exactly equal to v2 before inference.
Each allows at most three planned tasks, two attempts and three turns per task attempt,
12,288 context / 4,096 output tokens, and the unchanged pinned model/deployment.
Plans were generated by the local model. Workers wrote implementations and tests.
Implementation workers passed in all six runs; five complete builds halted on tests.
All trial responses, failed attempts and contracts are retained in `baseline-results.json`
and `results.json`. The accepted v4 trial-2 passes the held-out check and replays with
zero new events. Selection for delivery was the first accepted candidate.

The new context behavior closes a confirmed visibility gap, but these samples do not
prove a reliability improvement. Failed workers continued to assume cross-batch indices
or enabled foreign keys even with source and expected/actual diagnostics. The accepted
test worker passed its first candidate after a read; do not attribute its success solely
to automatic repair windows. Issue 66 records a bounded reasoning-profile comparison.

## Factory change

Up to two relative failure file/line locations select 25-line windows from the current
draft, including task-created files. Paths and lines are untrusted hints and grant no
new access. Explicit reads retain priority; total context stays within eight windows and
12,000 source bytes. Exact edits still bind current source and contract identity.
`retained-view.json` demonstrates the previously invisible failing assertion appearing
in a 2,439-byte source view without inference, edits or changes to historical ledger state.
Five new regression cases and the full suite pass: 508 tests and 25 subtests. Ruff, mypy,
and four historical accepted/halted/challenged replay checks pass.

## Portable reproduction

Create `.gflo/targets/ai-gamer-atomic-baseline` as a clean checkout of the pinned revision.
The runtime captures all 88 original files (271,757 bytes) but prepares only the selected
execution files. Current SourceBundle execution limits remain; this is not million-line
qualification. Run scripts from the factory root with `PYTHONPATH=. .venv/bin/python`:

- `campaign.py --output .gflo/evidence/atomic-moves-v2` freezes baseline fixtures and
  runs three trials. To reproduce the historical baseline behavior, use runtime 113e01e
  with this portable harness available; current runtime includes the new windows.
- A fresh output directory repeats the same requests/policies and checks their identities
  against v2. Existing output directories are refused; no exhausted run is reset.
- `preflight_heldout.py` checks original rejection and reference success for commit errors.
- `report.py --campaign DIRECTORY --output REPORT.json` exports all trials, audits accepted
  snapshots and replays acceptance. Do not rerun after contradictory findings without
  inspecting retained evidence first.
- `replay_view.py` projects the retained baseline failure without running the model.

The independently written reference method/tests and gates are qualification fixtures,
not worker proposals. Baseline failed preflight v1 is retained: the first test validator
incorrectly expected exception types in pytest XML; the corrected gate records real
exception types through a pytest hook and rejects crashes, skips and setup errors.
A v3 preparation attempt caught an accidental extra import in generated gate text before
inference. v4 restored identical gate bytes. Neither preflight/preparation failure spent
model responses. A held-out preflight logging typo also stopped before model work and was
corrected separately. All raw ledgers remain under ignored `.gflo/evidence/`.
