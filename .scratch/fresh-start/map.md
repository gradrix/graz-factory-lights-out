# GFLO fresh start

## Destination

Accepted initial release: a simple local software factory on MONSTER-GAMING-PC: a usable CLI runs bounded repository tasks through implementation, executable acceptance and bounded repair, retaining evidence and recovering from interruption. Qualify it with small real-world scenarios before extending functionality.

## Notes

User direction, 2026-10-01: scrap the previous architecture; start gradually; prioritize usability, modular functionality, robustness and predictable local operation. Use the tested improved 5090 model. SFLO and Gas City are inspiration only. Local files are the tracker, matching existing repository practice. User update 2026-10-02 deleted the reset archive and authorized publication. The new autonomy destination is tracked in ../autonomy/map.md.

## Decisions so far

- [Fresh local core](../../docs/decisions/architecture/001-fresh-local-core.md): three functional modules and offline execution, no inherited roadmap.
- [Initial acceptance](../../docs/decisions/product/001-initial-acceptance.md): bounded repository changes, checks, repair and recovery before autonomous decomposition.

- [Initial model profile](../../docs/decisions/architecture/002-model-profile.md): use the tested 128K/Q4 candidate; validate small tasks without claiming full-window coding reliability.

## Not yet specified

No unresolved decision blocks this release. Future increments must establish local semantic-review reliability, then task decomposition and larger-project acceptance. Current evidence and limitations are recorded in [pilot results](../../docs/pilot-results.md).

## Out of scope for the first release

Cloud inference, automatic production deployment, autonomous product strategy, self-modifying factory, fleet scheduling, UI dashboard, automatic merging into source repositories, and comprehensive large-project qualification.
